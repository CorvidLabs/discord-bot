# Adopt

## Intent

Somebody finds this and wants it for their own token and their own community. Everything they have to say about themselves should be something they say, not something they find in the source and edit: which asset, which collections, which rungs, which words their members read.

The fear is the fork that is nearly clean. Most of the branding comes out in an afternoon, and then a member in somebody else's server sees a picture nobody there chose, or a tier named after a word nobody there has ever said, or a wallet nobody there has heard of turns out to hold permanent admin over their roles. Each one is small on its own. Together they say plainly that this is a hand-me-down, and the operator found out from a member rather than from the bot.

So the rule this family exists to hold is that an unset thing is empty, never inherited. A blank logo is no picture rather than somebody else's picture. An unnamed ladder is no ladder rather than six rungs a stranger chose. Nothing the operator did not type should be able to appear in front of their members.

The second fear is a setup that is wrong but quiet. Configuration written by hand always has a typo in it, and the dangerous typos are the ones that leave something valid behind: a dropped rung, a collection that matches nothing, an id pointing somewhere other than where the operator believes it points. A bad value should stop the boot and name itself. A merely surprising one should at least be readable in what the bot says it made of the settings, before a sweep acts on it.

Not everybody wants all of it either. A community with a token and no art, or art and no token, or roles and nothing that ever sends anything, is a whole community rather than a partial one, and should never have to carry the parts it has no use for.

The test of it is simple and unkind. Somebody who has not read the source should get it running for their project from the README alone, and nothing in their server should give away whose bot it used to be.

## Criteria

- **ADOPT-1**  I can run this for my own token and community without editing code
  - **ADOPT-1.a**  The tiers are mine: my names, my thresholds, as many or as few as I want
  - **ADOPT-1.b**  My collections are mine: as many as I have, each saying what holding one earns
  - **ADOPT-1.c**  Nobody in my server ever sees a word from the project this was built for
  - **ADOPT-1.d**  The token is mine: which asset it is, what it is called and how many decimal places it has, so every figure a member reads is my token's
  - **ADOPT-1.e**  The pools I want counted toward a tier are mine to list, and none is a perfectly good list
  - **ADOPT-1.f**  The name the bot goes by, the words on its cards and the picture beside them are mine to set
- **ADOPT-2**  I find out I have set it up wrong before my members do
- **ADOPT-3**  The games are playable in my server without me owning somebody else's collections
  - **ADOPT-3.a**  What holding one of my collections is worth in a game is mine to set, and setting nothing leaves a game that still plays
- **ADOPT-4**  I can get from a clean machine to a running bot by following the README alone
- **ADOPT-5**  Upgrading to a newer version keeps my settings and my members' wallets
  - **ADOPT-5.a**  Renaming something of mine does not quietly orphan the records already kept under the old name
- **ADOPT-6**  Anything I have not set is empty rather than somebody else's
  - **ADOPT-6.a**  No picture, address, link, name or threshold from another project is ever what I get for leaving a setting blank
  - **ADOPT-6.b**  Having no tiers, no collections or no pools is a setup that runs rather than one that fails or invents some
- **ADOPT-7**  Nothing I copy to get started holds anybody's real server, wallet, asset or address
  - **ADOPT-7.a**  A placeholder I forgot to replace stops the boot rather than pointing my bot at a stranger's asset
- **ADOPT-8**  A value I give for one job is never quietly used for another
- **ADOPT-9**  When it starts I can read what it made of my settings, not only that it started
  - **ADOPT-9.a**  A rung, a collection or a pool that my typo dropped reads as missing there, before a sweep acts on it
- **ADOPT-10**  I can run only the parts I want, and the parts I leave out cost me nothing
  - **ADOPT-10.a**  A community with a token and no collections, or collections and no token, is a whole setup rather than a broken one
  - **ADOPT-10.b**  If I never want it to send anything, nothing in my server offers a way to, rather than offering one that then fails
